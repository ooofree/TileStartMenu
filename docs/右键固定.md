# 右键「固定到开始菜单」实现说明

## 功能

在桌面/任意位置的 `.lnk` 或 `.exe` 文件上右键，出现「固定到开始菜单 / 从开始菜单取消固定」两项；
点击后通过命令行 `--pin "<path>"` / `--unpin "<path>"` 转发给正在运行的 TileStartMenu 实例，
把目标解析成磁贴挂到「常用」分组，图标走 IconService 256px 提取。

## 注册表键路径（HKCU，无需管理员）

```
HKCU\Software\Classes\lnkfile\shell\TileStartMenu.Pin
  (Default) = "固定到开始菜单"
  Icon      = "<exe>,0"
  command\(Default) = "<exe>" --pin "%1"

HKCU\Software\Classes\lnkfile\shell\TileStartMenu.Unpin
  (Default) = "从开始菜单取消固定"
  Icon      = "<exe>,0"

HKCU\Software\Classes\exefile\shell\TileStartMenu.Pin        (同上)

```

写完注册表后，右键菜单可能要等 explorer 刷新才出现新项。跑一次：

```

```

## 行为细节

- `.lnk`：用 IShellLinkW 解析 TargetPath/Arguments/WorkingDirectory；Target 不存在则退化为直接把 .lnk 当 Launch 目标。
- `.exe`：直接当 Launch 目标。
- 名称：.lnk 取文件名去扩展名；.exe 同理。
- 颜色：`TilePalette.ColorForName(name)`；尺寸 Medium；分组「常用」；order 追加组尾。
- 去重：规范化 target（小写、去引号、统一分隔符）后已存在则不新增，日志记 `already pinned`。
- 成功后自动弹出开始菜单（菜单已开则就地刷新墙）。
- 图标：`IconService.RequestIcon` 异步取 256px 原始图标。
- 日志：`%LOCALAPPDATA%\TileStartMenu\ui-debug.log`，行格式 `PIN-FROM-CONTEXT ok=True name=... target=...`，并附 `RESOLVE arg=<原始入参> target=<解析后> matched=<命中或 none>`。

## 已修 bug

### Bug 1 — .lnk 路径 unpin 静默失败（已修）
**现象**：`--pin "X.lnk"` 把 .lnk 解析成 TargetPath（如 `Spotify.exe`）存进 tile；但 `--unpin "X.lnk"` 拿原始 .lnk 路径去和 `Spotify.exe` 比较，匹配不上 → `ok=False reason=not-pinned`。
**修法**：Unpin 入参同样走 `ShortcutResolver` 解析成 TargetPath，同时用**规范化后的 target** 和 **.lnk 原路径**两者比对，命中任一即删。

### Bug 2 — Unpin 只置 Pinned=false 导致孤儿累积（已修）
**现象**：pin→unpin→pin 反复会在 menu.json 堆出多条同名记录（实测 notepad + 2×Spotify 共 3 条孤儿）。
**修法**：`--unpin` 命中后**从 tiles 集合移除该条**；`--pin` 时若发现同 target 但 `Pinned=false` 的残留记录（UI 层 unpin 留下的），优先复用并改回 Pinned=true，而不是新建。

| `--pin Spotify.lnk` | 14 |
| `--unpin Spotify.lnk` | 13 |

### 5. Unpin 幂等与路径匹配 ⚠️（发现一个真实 bug）

- `--unpin "<Spotify.lnk>"`（即右键菜单 verb 传的 `%1`）：
  ```
  [19:16:53.643] UNPIN-FROM-CONTEXT ok=False reason=not-pinned path=<user>\Desktop\Spotify.lnk
  ```
  **失败**。因为 Pin 时把 .lnk 解析成了真实 target `Spotify.exe` 存进 menu.json，而 Unpin 用 .lnk 路径去匹配 target 字段，匹配不上。
- 改传解析后的 exe 路径：`--unpin "<user>\AppData\Roaming\Spotify\Spotify.exe"`：
  ```
  [19:17:08.389] UNPIN-FROM-CONTEXT ok=True name=Spotify
  ```
  成功。
- 再次 `--unpin "<Spotify.lnk>"`：仍 `ok=False reason=not-pinned`（第二次幂等）。

**bug 影响**：用户在桌面 `.lnk` 上右键选「从开始菜单取消固定」，verb 传的是 .lnk 路径，会因路径不匹配而 `ok=False`，取消固定静默失败。建议核心层在 Unpin 匹配时把传入路径也走一次 ShortcutResolver 解析后再比对 target，或在 menu.json 里额外存一份 sourceLnk 字段反向匹配。

### 5b. Unpin 行为：置 pinned=false 而非删除 ⚠️

实测发现 Unpin 不是从 tiles 数组移除条目，而是把 `pinned` 字段置为 false。这导致：
- menu.json 累积 `pinned=false` 的孤儿条目（本轮测试留下 notepad + 2 个 Spotify 共 3 条）；
- 再次 Pin 同一目标会**新建**一条 `pinned=true` 条目，而不是复用旧记录（日志虽然报 already pinned，但实际新增了一条）；
- 结果：menu.json 从 12 → 15 条，墙视觉上仍只显示 pinned=true 的，但文件膨胀。

测试结束后已手工清理这 3 条孤儿，恢复 12 磁贴 / 6404 字节。建议：Unpin 时直接从 tiles 数组删除该条目，或定期清理 pinned=false 孤儿。

- 但这是一个**UX 发现**：用户在 Win11 上右键默认看不到「固定到开始菜单」，需要多一步「显示更多选项」。若要让它在现代菜单直接出现，需要走 IExplorerCommand / MSIX 包的 modern context menu 注册（不是本版本范围）。
