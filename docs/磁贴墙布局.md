# 磁贴墙布局：列优先打包（v9 修复）

## 根因（为什么之前 12 个磁贴全挤在一行）

`MetroPack.Layout(sizes, limit)` 的第二个参数原本语义是「**列数上限**」，扫描顺序是
**行优先**（`for r … for c < limit`）：先把第 0 行从 c=0 一路向右铺，铺到 limit 列才换行。

但 `MainWindow.RebuildLayout()` 传进来的值是：

```csharp
int maxRows = Math.Max(2, (int)Math.Floor((viewH + Gap) / (Cell + Gap)));
MetroPack.Layout(sizes, maxRows);
```

这个值是按「纵向可用高度 ÷ 格高」算出来的、**表示"能放多少行"**。
于是一个"能放多少行"的值被当成"最多几列"传进了行优先扫描——
等于告诉打包器「这一行允许铺 N 列」，N 又很大，结果所有磁贴全部铺在 row 0 上从左到右一长条，
屏幕下半部整片空着。这就是旧截图里 12 个磁贴挤在 y≈370 同一行的直接原因。

## 修法

### 1. MetroPack.Layout 改为列优先，第二参数改名为 rowsPerColumn

```csharp
public static List<Rect> Layout(IReadOnlyList<Size> sizes, int rowsPerColumn)
{
    ...
    for (int c = 0; c < 4096 && !placed; c++)        // 外层：列
        for (int r = 0; r < rowsPerCol && !placed; r++) // 内层：行
            if (Fits(occupied, c, r, cols, rows)) { Mark(...); placed = true; }
}
```

- 一列自上而下填满 `rowsPerColumn` 行后才 `c++` 开下一列；
- 列数**不设上限**（横向扩展交给 `WallScroll` + 背景抓纸拖动 `WALL-DRAG`）；
- 尺寸占格口径不变：小 1×1、中 2×2、宽 4×2、大 4×4（`TileMetrics.Spans`）。
  宽/大磁贴用现有 `Fits/Mark` 占位集合整块占位，按列扫描时当前列放不下就 `c++` 再来，
  整块落在同一列组内、不跨列断开、不重叠、不悬空。

### 2. rowsPerColumn 按 DIP 算（不再拿物理像素）

```csharp
const double TopReserve = 90;     // 顶部时钟/电源/齿轮留白
const double BottomReserve = 80;  // 底部「所有应用 ↓」条
double usableH = Math.Max(ActualHeight - TopReserve - BottomReserve, 300);
int rowsPerColumn = Math.Max(2,
    (int)Math.Floor((usableH + Gap) / (Cell + Gap)));
Dbg($"LAYOUT rowsPerColumn={rowsPerColumn} usableH={usableH:0.0} actualHeight={ActualHeight:0.0}");
```

WPF 的 `ActualHeight` 本就是 DIP，**禁止**再乘 DPI 缩放或调 `GetSystemMetrics`。
每次 `RebuildLayout()` 都会把这三个值写进 `%LOCALAPPDATA%\TileStartMenu\ui-debug.log`，
用于核对高 DPI 下是否又被算成 1。

### 3. 分组仍是独立多列块

- 组标题仍挂在 `TileCanvas`（真 Canvas）上、`IsHitTestVisible=false`，位置在该组第一列左上方；
- 组间 `GroupGap = 60`；组内列数随磁贴数自动向右扩展；
- 垂直居中仍按「最高组内容高度」整体居中：`vOffset = (ActualHeight - maxGroupH)/2 - 10`。
  新布局下 `maxGroupH` ≈ `rowsPerColumn*Pitch`，整块依然落在屏幕垂直居中带，
  组标题 = `vOffset - HeaderHeight - 12`，不会压到顶部时钟。

### 4. 拖拽落点同步

`UpdateDragPosition()` 里复用同一套 `MetroPack.Layout`，第二参数同样改用
按 `PanelHeight`（= usableH）算出的 `rowsPerColumn`，drop outline 预览与真实布局同语义。

## 可观测性（v9 追加）
- 每次 `RebuildLayout()` 除打印 `LAYOUT rowsPerColumn=… usableH=… actualHeight=…` 外，逐块打印
  `LAYOUT tile=<name> col=<c> row=<r> cols=<w> rows=<h>`（单位为 unit 格，小=1×1）。
- 排布完成后内部自检：两两矩形重叠、或底部超出 `rowsPerColumn*Pitch` 上限时打印
  `LAYOUT-VIOLATION …`；正常布局不出现该日志。
- 空洞回填（桥洞规则）：**仅 1×1 小磁贴**允许回填"该列下方已有内容"的悬空空位（宽/大磁突出去后留下的）；
  **2×2 及以上（中/宽/大）严格列优先**——先把 x=0 列自上而下填满 rows0-13，满了才开第二列。
  取舍：对齐用户"两个小=一个中、两个中=一个大"的视觉语义，小磁贴补桥洞拼出整块中/大；
  但中/宽/大如果也跳去填桥洞，会把第二列提前开到 rows0，破坏"填满一列再右扩"的主视觉。

## 验收对照

| 场景 | 预期 |
|---|---|
| 默认 12 磁贴 | 至少 2 行纵向叠放，屏幕下半被利用，不再单行铺 |
| Pin 到 20+ | 一列满后自动开第二列 |
| Pin 到 40+ | 整屏多列铺满，超屏靠 `WALL-DRAG` 拖动翻页 |
| 小/中/宽/大混排 | 无重叠、无半截悬空、组标题不压磁贴 |
| 组标题/时钟/⏻/齿轮/所有应用 | 仍可见可点；`ZOOM enter` 组块数=组数 |

## 布局自检表（`--layout-test` 无头入口）

入口：`TileStartMenu.App.exe --layout-test`，启动早期判断参数后直接跑完 `MetroPack.Layout`、把
unit 坐标表写进 `%LOCALAPPDATA%\TileStartMenu\layout-test.log` 后 `Shutdown(0)`。
不建窗口、不碰 menu.json、不抢焦点。

### unit 网格语义（唯一尺寸基准）
- 一个 unit = 小磁贴占地（1×1，已含 gap）。
- 尺寸口径：**小 1×1、中 2×2、宽 4×2、大 4×4**（单位均为 unit）。
- 对齐推论：两个小磁贴纵向叠 = 2 unit 高 = 一个中磁贴高；两个中磁贴纵向叠 = 4 unit = 一个大磁贴高。
- 所有磁贴边必须落在 unit 网格线上，不允许半格偏移。
- `rowsPerColumn=14`（真机 DIP 算得：`usableH=ActualHeight-90-80=896.7`，`(896.7+6)/(56+6)≈14`）。

### CASE-1 对齐（中,中,小,小,中,小,小,宽,大）
```
idx name size x  y  w  h
1   中1   M    0  0  2  2
2   中2   M    0  2  2  2
3   小1   S    0  4  1  1
4   小2   S    0  5  1  1
5   中3   M    0  6  2  2
6   小3   S    1  4  1  1
7   小4   S    1  5  1  1
8   宽1   W    0  8  4  2
9   大1   L    0  10 4  4
COLUMNS=4  VIOLATION=none
```
核对：小1(0,4)+小2(0,5) 底边 y=6 == 中3(0,6) 顶边；两小=一中高。小3/小4 回填到 (1,4)/(1,5)，
与小1/小2 拼成 2×2 == 一个中。宽1(0,8)、大1(0,10) 续在本列下方（大占 rows10-13 正好满 14 行）。

**为什么第 8 块(宽)在 rows8、第 9 块(大)在 rows10？** 这是"找最早能整块容纳的空位"的自然结果，
不是随手排的：x=0 列在中3(rows6-7)之后只剩 rows8 往下；宽要 4×2，落在 rows8-9；大要 4×4，
落在 rows10-13（刚好不越界）。两者都在已占包围盒内找不到别的整块空位，就顺序续在列底。

### CASE-2a 列尾余格（中×6,小,小,中）
```
idx name x  y  w  h
1-6 中1..中6 0  0..10  2 2   (rows0-11 满)
7   小1    0  12 1 1
8   小2    0  13 1 1
9   中7    1  12 2 2
COLUMNS=3  VIOLATION=none
```
两个小磁贴正好落在列尾剩余的 (0,12)/(0,13) 单行格，不开新列；中7 填 (1,12) 收尾，不越界。

### CASE-2b 桥洞回填（中,宽,小）
```
idx name x  y  w  h
1   中1   0  0  2  2
2   宽1   0  2  4  2
3   小1   2  0  1  1
COLUMNS=4  VIOLATION=none
```
中(0,0) 只占 cols0-1；宽(0,2) 跨 cols0-3 rows2-3，于是 cols2-3 rows0-1 成了"悬空桥洞"
（其下 rows2-3 已有宽磁贴内容）。小1 被回填进 (2,0)，而不是顺着列底跑到 (0,4)。
判定规则：只回填"该列在其下方已有内容"的桥洞，不回填还在向下长的活动列旁空位。

### CASE-3 单组 12 个中
```
idx name x y w h
1-7  中1..中7  0  0..12  2 2   (第 1 个磁贴列，7 个满 14 行)
8-12 中8..中12 2  0..8   2 2   (第 2 个磁贴列)
COLUMNS=4  VIOLATION=none
```
14 行 ÷ 2 行/中 = 7 个/列，12 个跨 2 个磁贴列（unit 列 0-1 与 2-3），组宽由实际占用算出。

### CASE-4 两组宽度不同
```
GROUP-A colStart=0 colSpan=4 unit (12 medium)
GROUP-B colStart=0 colSpan=2 unit (2 medium)
WIDTHS-DIFFER=True
```
组宽不固定，由实际占用列数决定；窄组(B)不与宽组(A)打架。
