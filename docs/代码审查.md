# 代码审查报告

> 审查范围：Core（Hotkey / Icons / Catalog / Power / Persistence / Launcher / Models）与 UI（App.xaml.cs、AppHost/*、MainWindow.xaml.cs、TileControl、AllAppsView）。
> 审查方式：通读源码 + Release 构建输出 + 运行日志交叉验证。**本审查不修改代码**，仅列问题与建议。
> 注意：UI 同事正在重写 MainWindow.xaml.cs，行号以本次审查时磁盘版本为准（横向布局版）。

## 一、高危问题（建议本轮内修）

### P0-1　电源服务未注入 UI，电源按钮/电源磁贴整体不可用
- **位置**：`App.xaml.cs:74`（`new MainWindow(_store, _launcher, _icons)`）；`App.xaml.cs:40-42` 只暴露 `Store/Icons/Catalog`，**没有 `Power` 属性**；`MainWindow.xaml.cs:100` `_power = power ?? TryGetProperty<IPowerService>(app, "Power")`；`MainWindow.xaml.cs:666-672` `PowerConfirm_Click`。
- **现象**：`TryGetProperty(app,"Power")` 在 App 类上找不到该属性 → `_power` 恒为 null。点击右上 ⏻ 或「系统」组任一电源磁贴，走到确认面板点「确定」时：`_power != null && _power.Execute(...)` 恒为 false → 永远弹错误条「电源操作失败：IPowerService 尚未就绪」。`PowerService` 实例只在 `SeedAllApps`（App.xaml.cs:199）里 new 了一下跑 DryRun 就丢弃。
- **建议**：App 装配 `_power = new PowerService()` 并暴露 `public IPowerService Power`，构造 MainWindow 时传入；再跑一次电源 DryRun 后复测按钮。

### P0-2　电源二次确认只存在于 UI 层，Core 侧 Execute 无任何防护
- **位置**：`Power/PowerService.cs:59-88`（Execute 直接 `ExitWindowsEx`/`SetSuspendState`）；确认逻辑全在 `MainWindow.xaml.cs:648-674`。
- **现象**：契约 §5 要求关机/重启有二次确认，但 Core 层 `Execute(action)` 签名无 confirm 参数、无令牌。任何未来的调用方（UI 重构、快捷键、脚本）一键即真实关机/注销，无最后防线。另外 `LaunchTile`（MainWindow.xaml.cs:617-621）点电源磁贴时先 `OpenPowerChooser()` 再立刻 `PowerChoice_Click(new Button{Tag=...})`，靠代码硬跳浮层状态机，Chooser 列表刚显示就被ConfirmPanel替换，状态脆弱。
- **建议**：Core `Execute` 增加显式 `bool confirmed` 参数（关机/重启未确认直接返回 false）；电源磁贴点击改为只打开 Chooser，由用户再选动作，不要代码连跳两步。

### P1-3　默认浏览器磁贴把字面量 `%1` 当参数传给浏览器
- **位置**：`App.xaml.cs:214-241` `ResolveDefaultBrowser`；实证见 `%LOCALAPPDATA%\TileStartMenu\menu.json`：msedge 磁贴 `"arguments": "\"%1\""`。
- **现象**：从 `HKCR\http\shell\open\command` 解析时把整个参数串原样存下，含未替换的 `%1` 占位符。点该磁贴会把字面量 `"%1"` 作为命令行参数传给 msedge（Edge 会把它当奇怪参数/搜索词）。
- **建议**：解析后剔除 `%1`、`%*`、`--` 等占位参数（或干脆不存 arguments，浏览器磁贴本就该无参启动）。

### P1-4　Pin 落点 Order 计算运算符优先级错误
- **位置**：`MainWindow.xaml.cs:1007` 与 `:1016`：
  `...Max(t => (int?)t.Order) ?? 0 + 1`
- **现象**：C# 中 `??` 优先级低于 `+`，实际语义是 `Max(...) ?? (0+1)`。非空分组时新磁贴 Order = 组内**最大 Order 本身**（与末尾磁贴撞号），而不是 max+1。目前靠 `MenuConfig.Normalize()` 按 Order 重编号兜底才没出乱子，但插入位置依赖列表顺序，脆弱且违背代码意图。
- **建议**：改为 `(cfg.Tiles.Where(...).Max(t => (int?)t.Order) ?? 0) + 1`，并补一个空分组/非空分组的单测。

### P1-5　紧急恢复热键会自等待约 2 秒
- **位置**：`WinKeyHookService.cs:309-323`（钩子线程内 `EmergencyRestoreRequested?.Invoke`）；`App.xaml.cs:68-71`（订阅里 `Dispatcher.Invoke(...)`）→ `EmergencyRestore()` → `_hook.Stop()` → `TryStopThread()` 里 `t.Join(2s)`。
- **现象**：Ctrl+Alt+Shift+Esc 在**钩子线程**里同步 `Dispatcher.Invoke` 到 UI 线程；UI 线程执行 `Stop()` 又 `Join` 钩子线程 2 秒——钩子线程正卡在等 UI，Join 必然超时（2s）后才继续。表现为紧急恢复触发后 UI 冻结约 2 秒。
- **建议**：事件订阅改 `Dispatcher.BeginInvoke`；`Stop()` 里对"自己就是钩子线程"的情形跳过 Join（或只 PostThreadMessage 不等 Join）。

## 二、中危问题

### P2-6　托盘「打开配置目录」实际打开的是 menu.json 文件
- **位置**：`App.xaml.cs:318-326`：`Process.Start(new ProcessStartInfo{ FileName = _store.ConfigPath, UseShellExecute=true })`。
- **现象**：ConfigPath 是 `...\TileStartMenu\menu.json` 文件，会用默认编辑器打开 JSON，而不是资源管理器打开配置目录。
- **建议**：改为打开 `_store.RootDir`（或 `explorer.exe <RootDir>`）。

### P2-7　图标提取被一把大锁全局串行，UI 线程可能被卡住
- **位置**：`Icons/IconService.cs:108` `lock (_gate)` 包住整段 `GetIconPngPath`（含耗时 COM 调用，explorer 样本 177ms）；`MainWindow.xaml.cs:733-740` `GetIconPathFor` 在 UI 线程同步调用它。
- **现象**：`SemaphoreSlim(2)` 并发形同虚设（同一时刻只能一个进 lock）；切图标规格（CycleIconScale）时 UI 线程同步做 Shell 图标提取，首帧可能掉一下。
- **建议**：lock 只保护缓存字典读写，提取过程放到锁外 + 并发字典；`GetIconPathFor` 走异步路径。

### P2-8　构建存在 6 条可空引用警告（MainWindow.xaml.cs 405/411/412 一带）
- **位置**：构建输出 `CS8600`（`(TileControl)sender` 强转）、`CS8602`（`Canvas.GetLeft(_pressTile)`、`Canvas.GetTop(_pressTile)` 在 `_pressTile` 可能 null 时调用）。
- **现象**：当前靠 try/catch 兜着，但若 sender 类型异常会抛进 `Tile_MouseLeftButtonDown` 的 catch，点击静默失效。
- **建议**：强转后判空返回；`_pressTile` 用局部变量捕获后再取 Canvas 坐标。

### P2-9　种子实际只产出 5 个基础磁贴，缺「终端」
- **位置**：`App.xaml.cs:152-155`（wt.exe → WindowsTerminal.exe → powershell.exe 回退）；实证 `seed-migration.log` 迁移后 10 条 = 5 基础 + 5 电源，menu.json 当前也无终端磁贴。
- **现象**：迁移发生时该回退链未产出终端磁贴（历史版本产物）；当前代码 `ResolveExecutableOnPath("powershell.exe")` 理论能命中 System32，但未用全新 `%LOCALAPPDATA%` 复测。
- **建议**：清目录首启一次，确认 6 基础磁贴齐全；若 wt.exe 不存在应记日志说明回退到了谁。

### P2-10　调试日志无轮转、生产常开探针
- **位置**：`MainWindow.xaml.cs:393-396`（Dbg 每次点击/按下都 append ui-debug.log，文件已 24KB+ 且持续增长）；同 `WinKeyHookService.Diag`、`TimingLog` 只追加不截断。
- **现象**：长期使用日志无限增长；`WINDOW-DOWN` 探针每次按下都写盘。
- **建议**：按大小/日期轮转，或加编译常量开关 Release 关探针。

### P2-11　空分组无法删除
- **位置**：`MainWindow.xaml.cs:743-754` OpenWallCustomizeBar 只有「新建分组/重命名分组/主题色」；menu.json 现存空组「工具」「网页」。
- **现象**：Normalize 不会清空空组，用户也没有删除入口，空组永远占位。
- **建议**：App Bar 加「删除空分组」，或 Normalize 时移除无磁贴且非用户保留的组。

## 四、重点关注项的结论

| 关注项 | 结论 |
| --- | --- |
| 点击与拖拽判定 | 位移驱动（阈值 6px），慢按 511ms 仍判点击（ui-debug 实证）；长按 250ms 只置 armed 不误触发拖拽；`_pressSerial` 防过期按下。设计正确。 |
| 虚拟化回收导致事件丢失 | 有窗口级 `MouseLeftButtonUp` 兜底（handledEventsToo）+ `_pressTile` 引用，磁贴滚出可视区被回收后 Up 仍能收尾；拖拽中的磁贴被排除回收（`c != _pressTile`）。正确。 |
| 线程与 UI 线程边界 | 钩子在专用线程、事件一律 `Dispatcher.BeginInvoke` 回 UI；图标提取在 ThreadPool、回 UI 用 `DispatcherPriority.Background`；枚举在 `Task.Run`。边界清晰。例外见 P2-7（UI 线程同步取图标）。 |
| 异常被吞 | 多处空 `catch { }`（托盘、钩子、图标、配置），符合"不崩"目标，但会掩盖问题；建议至少写 debug 日志。 |
| 电源动作安全性 | **不足**：二次确认只在 UI，Core 无防护（P0-2）；且当前 UI 根本调不到 Core（P0-1）。 |
| 钩子卸载与退出顺序 | `OnExit` 先 `_hook.Stop()` 再 `_tray.Dispose()` 再 `_single.Dispose()`；紧急恢复路径见 P1-5（2s 冻结）。 |
| 配置原子写 | `JsonConfigStore.Save`：tmp → File.Replace，锁内 Normalize+序列化；损坏备份 `.broken-*` 后重建。正确。 |
